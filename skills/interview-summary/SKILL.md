# Interview Summary

## Purpose

Use this skill to produce high-quality interview summaries that are easy to review later. The default goal is not a short abstract. The goal is a faithful, structured recap that preserves how the conversation moved and how the guest supported each claim.

## Default Approach

Default to summarizing the interview by the host’s or interviewer’s core questions.

For each major question block, cover:

- what the host is really asking
- the guest’s direct answer
- how the guest develops the answer
- what evidence, examples, numbers, stories, or comparisons the guest uses

Do not jump too early to your own thematic buckets unless the user explicitly asks for that. Preserve the original conversational logic first, then compress at the end if useful.

## What Good Output Looks Like

A good summary should:

- follow the interview’s actual progression
- make the guest’s reasoning easy to reconstruct later
- retain key examples, proof points, and turning points
- clearly capture business, growth, revenue, profit, margin, fundraising, adoption, or timeline claims when they appear
- be detailed enough that the user can re-read it later as a study note

The summary should not flatten everything into generic themes like `vision`, `strategy`, or `future` if the original interview was more specific.

## Required Habits

When summarizing, always try to preserve these layers:

1. The host’s core question
2. The guest’s direct answer
3. The guest’s argument structure
4. The supporting evidence or examples

If the interview includes important numbers or timing, keep them explicit:

- revenue figures
- profit or loss claims
- ARR, margins, growth rates, conversion figures
- dates, years, quarters, or “within 1-2 years” style timelines
- product launch order or organizational changes

If the interview includes a meaningful contradiction or tension, make it legible rather than smoothing it over. For example:

- fast growth but constrained hiring
- strong AI timelines but cautious capital deployment
- safety orientation but aggressive commercialization

## Preferred Output Shape

Unless the user asks otherwise, organize the summary as a sequence of sections, one per major host question or question cluster.

Within each section, prefer this rhythm:

- the host’s question or concern
- the guest’s main position
- the logic or mechanism behind that position
- the evidence, anecdotes, or data used to support it

Then optionally end with a short synthesis:

- the guest’s overall worldview
- the 3-5 biggest takeaways

## Important Corrections To Make While Summarizing

Avoid these common failure modes:

- summarizing by your own themes instead of the interview’s question flow
- dropping the commercial or financial middle of the argument
- keeping only conclusions while losing the reasoning
- omitting examples that actually make the argument persuasive
- over-compressing to the point that the result is not useful for future review

If a user cares about interview summaries, assume they usually want something they can study later, not a tweet-length recap.

## When The User Wants More Detail

If the user asks for a very detailed version, expand each section with:

- hidden assumptions
- internal tensions in the answer
- what the speaker seems most confident versus least confident about
- where the host pushes back and how the guest responds

This is especially useful for founder, investor, operator, research, or policy interviews.

## When The User Wants A Shorter Version

If the user asks for a compact version, still keep the host-question structure, but compress each section to:

- question
- answer
- key evidence

Do not collapse everything into a single paragraph unless the user explicitly asks for a very short abstract.
